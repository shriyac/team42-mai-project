Examples you can map
directly to your service.

The JSON appendix contains complete response envelopes. It complements the route-specific request samples and the field dictionary.

How to read the examples

Every ID, account and date is fictional. Copy the structure, not the sample authorization or verdict.

For the live backend, replace IDs with records returned by the current workspace and use a real test account for each role.

The passed-review example is synthetic. Its hash matches the example text only, its law revision is a placeholder, and its timestamps expire.

Two different sample files

contracts/integration-examples.json contains request fixtures. docs/integration-guide-examples.json contains the response examples printed in this handbook.

Required means present

Keep required nullable fields present with null when unknown. Omit optional fields only when permitted. Extra undeclared object fields are rejected by most DTO schemas.

Use the correct example for the task

An empty landlord workspace is a valid bootstrap shape, not a substitute for a failed database read. A processing policy is durable accepted metadata, not ready evidence. A clarification answer is a safe supported workflow outcome when a legal check is missing; do not include unreviewed advice in its text.

Validate examples and real responses with the same OpenAPI version. The machine-readable spec remains authoritative for fields and envelopes; the implementation chapters explain ownership, date boundaries and security requirements that schemas cannot prove.
