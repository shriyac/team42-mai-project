Production RAG activation is an operator approval boundary, not an automatic
consequence of installed packages, available credentials, or successful mock
tests. Never auto-approve ownership from tenant names, filenames, or PDF text.

**Why:** The team's independent UI and RAG datasets do not establish a verified
common tenant/organization/lease registry. Example material includes synthetic
unsigned fixtures and unconfirmed template boilerplate, not proof of a real
tenant's executed contractual terms.

**How to apply:** Keep production retrieval disabled until actual authoritative
bindings, corpus/snapshot provenance and genuine service checks are approved.
Mock tests establish code behavior only; do not describe them as live Pinecone
verification or use them to approve real mappings.

Upstream format compatibility is not proof of compatibility with the actual
indexed corpus. Keep independent ingestion provenance and approval gates even
after importing teammate code.

**Why:** The same snapshot schema and embedding profile can accompany different
chunk extraction behavior, record identities, or reused namespace contents.
Matching code or total namespace counts cannot prove which corpus is active.

**How to apply:** Compare actual pinned ingestion inputs and corpus identities,
and verify authorized records in both indexes. Fail closed on stale canonical
citations; never generate an operational snapshot or approve a binding just
to make compatibility tests pass.
The user approved a disabled-by-default synthetic-demo exception for the
explicitly reviewed fixture, not general eligibility for unsigned documents.

**Why:** Controlled fixture demos are needed without weakening real production
eligibility or pretending an unsigned document is legally signed.

**How to apply:** Pin the exact approved identity and PDF hash, retain the
synthetic/unsigned status, visibly disclose demo status, and preserve all
ownership, manifest, snapshot, resource and evidence checks. Source eligibility
never approves ingestion or bindings. Do not relabel fixtures as signed.

Backend document identities and Pinecone document identities are distinct.
Retain the original source identity rather than replacing it to make an
unverified mapping appear aligned.

**Why:** Independent team implementations can use different identifiers.
String replacement hides ownership mistakes and damages citation provenance.

**How to apply:** Authorize any association through explicit, verified
server-owned mappings and preserve the original source metadata on evidence.

Preserve operator-supplied namespace spelling exactly; never autocorrect a
resource identifier.

**Why:** The user explicitly specified `laga-hydrid`, not `laga-hybrid`, as the
verified target namespace.

**How to apply:** Require exact agreement between configured and actual
snapshot namespaces. Report a mismatch rather than renaming or normalizing it.

Live demo approval must assess substantive answers, not just supported statuses
and valid citation identifiers.

**Why:** Real retrieval can return authentic but irrelevant clauses, unchecked
template alternatives, and incomplete PDF fragments. Structural validation
alone previously made these appear to be successful supported answers.

**How to apply:** Retest missing-evidence abstention alongside positive cases.
Inspect the actual operative clause and its conditions, not only the status,
source identity, or test count. Keep unknown question types conservative.
